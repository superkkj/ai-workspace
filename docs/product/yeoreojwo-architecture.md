# 열어줘 — 구현 구조와 데이터 규칙

- 결정일: 2026-11-18 (Asia/Seoul)
- 기획 원본: [첫 버전 기획](yeoreojwo-plan.md)
- 소스: `apps/yeoreojwo/`
- 실행 결과의 기준: [검사 기록](../ai/CHECKS.md). 이 문서의 구조 설명 자체는 검사 통과 증거가 아니다.

## 선택한 구조

React·TypeScript 화면과 Vinext 서버 라우트를 하나의 웹 프로젝트로 관리한다. 서버는 Cloudflare Worker 형식으로 빌드하고 D1에 구조화된 데이터를 저장한다. 기존 저장소에는 앱 코드나 기술 스택이 없었으므로, 별도 API 서버·DB 계정·지도 API 키 없이 첫 사용자 흐름을 실행할 수 있는 범위로 선택했다.

호스팅 환경의 ChatGPT 인증을 사용한다. 로그인 식별자는 서버에서 받으며, 클라이언트가 전달한 소유자 ID나 역할은 권한 근거로 사용하지 않는다. 공개 닉네임은 따로 설정한다. 인증 이메일과 원본 사용자 ID는 공개 목록·상세 응답에서 제외한다.

공개 GitHub에는 코드, 스키마, 마이그레이션, 합성 테스트 자료만 저장한다. 실제 사용자 글, 로컬 DB, 환경값과 인증 자료는 커밋하지 않는다. 저장소 공개 범위와 앱 방문 범위는 별개다. 새 호스팅 앱은 소유자 전용으로 시작하며 공유 범위 변경은 별도 요청을 따른다.

## 화면과 서버의 계약

`lib/contracts.ts`가 공개 데이터 형식의 기준이다.

- `GET /api/platform`: 로그인 여부와 공개 닉네임, 요청·제안·참가 집계를 반환한다.
- `POST /api/platform`: 명시된 한 행동을 수행하고 성공 또는 오류 코드와 한국어 메시지를 반환한다.
- 저장 성공 후 화면은 서버 상태를 재조회한다. 저장 실패를 화면상 성공으로 처리하지 않는다.
- 각 요청은 로그인한 사용자가 작성자·관심 참여자·확정자인지만 알려주는 불리언 값을 포함한다. 타인의 내부 식별자 목록은 반환하지 않는다.

| 행동 | 서버가 확인할 조건 |
| --- | --- |
| 닉네임 저장 | 로그인, 길이와 공개 입력 규칙 |
| 요청 작성 | 프로필, 제목·설명·지역·범위·예산·인원·미래 마감 |
| 관심 등록·취소 | 요청 상태, 본인 중복 방지, 작성자 최초 관심 |
| 제안 작성 | 타인 요청, 모집 상태, 미래 일정, 가격·최소 인원·정원, 안전한 선택형 링크 |
| 제안 선택 | 요청 작성자, 동일 요청의 유효한 제안, 아직 미선택 |
| 참가 확정·취소 | 선택된 제안, 시작 전, 본인 자리, 운영자 제외, 정원 |
| 모임 취소 | 작성자 또는 선택된 운영자, 취소 사유 |
| 완료 기록 | 작성자 또는 선택된 운영자, 종료 시각 이후, 최소 확정 인원 |

## 데이터 원칙

관심 수는 수요 표현이며 예약·결제 수가 아니다. 요청의 희망 인원, 제안의 최소 참가 인원, 제안의 최대 정원을 구분한다. 제안 선택 시 관심 참여자를 자동으로 확정하지 않는다.

중복 관계에는 DB 고유 제약을 둔다. 정원과 상태는 데이터를 쓰는 SQL에서도 확인하여 동시에 들어온 요청 때문에 초과 예약되지 않게 한다. 날짜는 서버 시각으로 판단하고, 입력과 표시의 사용자 기준은 Asia/Seoul이다.

선택한 제안의 날짜·가격·장소·정원은 확정 이후 변경하지 않는다. 이 조건을 바꾸려면 취소 후 새 요청을 작성한다. 원본 기록은 취소 상태로 남긴다. DB 스키마 변경은 마이그레이션으로 수행하고 요청 처리 중 테이블을 생성하지 않는다.

## 예시와 실제 데이터

`lib/examples.ts`의 예시는 화면 이해용이다. 카드·상세에 예시라고 표시하고 실제 DB에 저장하지 않는다. 예시에는 관심·제안·참가 확정 같은 변경을 적용하지 않는다. 실제 요청이 없을 때 0건 상태를 보여주며 예시 인원을 실제 이용자 수로 계산하지 않는다.

## 검증 범위

1. 입력·시각·URL·상태 규칙을 단위 검사한다.
2. 실제 서비스 SQL을 SQLite 어댑터에서 실행해 여러 사용자, 중복 요청, 마지막 자리 경쟁, 취소·완료 조건을 검사한다.
3. 실행 환경이 갖춰지면 로컬 D1과 HTTP 경로를 확인한다. 합성 테스트 사용자는 운영 인증 계정과 구분한다.
4. 브라우저에서 탐색·상세·폼·빈 결과·오류·좁은 화면을 확인한다.
5. 배포 도구가 성공을 반환한 경우에만 배포 완료로 기록한다. 사용자 PC 실행, 공개 모집, 실제 수업 성사는 별도 확인 항목이다.

## 다음 단계로 미루는 기능

결제·환불·정산, 실시간 채팅, 문자 발송, 지도·추천 AI, 운영자 자격 인증, 이미지 업로드는 첫 흐름에 포함하지 않는다. 일반 이용자를 받기 전에는 신고·운영 절차와 참가자 연락 수단을 실제 운영 방식에 맞춰 추가 검토한다.
