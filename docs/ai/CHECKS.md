## 열어줘 구현·검사 기록 — 2026-11-18

### 서버 규칙과 영속 데이터

- 실제 준비된 SQL을 Node 내장 SQLite에서 실행하는 D1 어댑터로 검증했습니다. 업무 로직을 흉내 낸 별도 가짜 구현만 검사한 것은 아닙니다.
- 요청·제안 입력, 닉네임·URL 검증, 로그인·소유자 권한, 관심과 확정 구분, 중복 참여, 마지막 자리 경쟁, 마감·취소·완료 조건과 공개 응답을 검사했습니다.
- 최신 공개 200개 밖의 내 요청·관심·제안·참가 기록을 유지하는 회귀 검사와, 공유 링크의 focused request ID로 오래된 요청 및 제안을 가져오는 회귀 검사를 포함합니다.
- 초기 검토에서 재현된 과거 내 활동 누락은 수정 후 재검토했습니다. 최종 재점검에서는 타입 검사와 24개 테스트 성공을 확인했습니다.
- 최소 인원이 충족돼도 시작 시각·시작 직후·종료 1ms 전에는 완료를 거절하고 정확한 종료 시각부터 허용하는 검사를 추가했습니다. 선택 전 제안을 철회하고 새 조건으로 다시 제출한 뒤, 이전 제안 ID는 거절하며 새 제안을 선택·확정하는 검사도 추가했습니다.
- 실제 원격 D1에서 동시 부하를 가하거나 실제 서로 다른 가입 계정의 브라우저 흐름을 끝낸 결과로 확대해서 설명하지 않습니다.

### HTTP 검사 실패 이력과 최종 수정

1. 관리형 미리보기와 실행 환경 사이의 loopback 연결은 `ECONNREFUSED`로 실패했습니다. 통과로 계산하지 않습니다.
2. 초기 [44257478542](https://github.com/superkkj/ai-workspace/actions/runs/44257478542)와 [44257980723](https://github.com/superkkj/ai-workspace/actions/runs/44257980723)는 401·403 뒤 첫 정상 저장 요청에서 평문 503으로 실패했습니다. 정상 GET 10회를 기다리는 조건도 해결책이 아니었습니다.
3. [44258530492](https://github.com/superkkj/ai-workspace/actions/runs/44258530492)에서는 당시 22개 테스트와 HTTP 9개가 통과했지만, 정확한 원인을 해결했다고 기록하지 않았습니다. 이후 테스트를 24개로 늘린 [44260337296](https://github.com/superkkj/ai-workspace/actions/runs/44260337296)에서 같은 503이 재발했습니다. 서버 로그에는 응답 후 요청 스트림 읽기 오류와 Broken pipe가 남았습니다.
4. Wrangler 4.92.0의 dev 번들링을 켠 [44261445927](https://github.com/superkkj/ai-workspace/actions/runs/44261445927)에서도 8 KiB 본문의 인증 거절 직후 다음 POST가 503으로 실패했습니다. 미들웨어 추가만으로 해결된 것으로 보지 않습니다.
5. [Cloudflare의 원문 이슈](https://github.com/cloudflare/workers-sdk/issues/15203)에서 수정된 런타임을 확인했습니다. 앱의 Wrangler·workers-types 직접 갱신은 기존 Vite 플러그인 peer 충돌을 만들어 적용하지 않았고, 앱의 원래 manifest·lockfile을 복원했습니다. 강제 의존성 설치는 사용하지 않았습니다.
6. `.github/tools/yeoreojwo-http-runtime/`에 Wrangler **4.151.2**를 독립 lockfile로 설치했습니다. 앱과 도구 각각의 `npm ls`가 성공했습니다. 첫 독립 런타임 실행 [44262489461](https://github.com/superkkj/ai-workspace/actions/runs/44262489461)은 폐지된 `legacy_env` 설정 때문에 DB 준비에서 실패했고 HTTP 검사는 실행되지 않았습니다.
7. `prepare-config.mjs`로 생성된 검사 설정의 `legacy_env: true`만 제거했습니다. 새 도구의 기본 동작과 같은 값일 때만 처리하며, 다른 값이면 실패합니다. Worker JS·정적 파일·DB 바인딩·`no_bundle`과 호스팅 배포 설정은 변경하지 않습니다.
8. **[최종 실행 44262860146](https://github.com/superkkj/ai-workspace/actions/runs/44262860146) 전체 성공.** 잘못된 JSON·알 수 없는 작업의 상태/코드 2개, 8 KiB 본문의 401/403 뒤 바로 다음 POST가 정상 응답하는 **20쌍**, 기존 실제 HTTP 사용 흐름 **9/9**가 모두 통과했습니다. 각 POST를 자동 재시도하지 않았습니다. 이번 실행의 합성 사용자·로컬 데이터만 정리했고 정리 성공 로그를 확인했습니다.

최종 HTTP 검사는 동일 앱 빌드 산출물을 별도로 고정한 로컬 런타임에서 실행한 결과입니다. D1 준비·서버·정리는 같은 CLI와 `.wrangler/state`를 사용합니다. 이전의 ‘Worker 재시작’ 오류 문구만으로 실제 재시작을 단정하지 않았으며, 확인된 거절 직후 연결 문제와 수정 범위는 [LESSONS.md](../../LESSONS.md)에 남겼습니다.

실제 여러 ChatGPT 계정을 사용한 호스팅 브라우저 전체 흐름, 원격 D1 부하 시험과 사용자 PC 실행은 여전히 미검증입니다. 테스트 런타임을 교체했다고 호스팅 내부 런타임까지 수정·검증했다고 주장하지 않습니다.

## 실행 결과를 남기는 방법

작업별로 날짜, 대상 변경, 명령 또는 확인 방법, 실행 위치와 환경, 관찰 결과를 기록합니다. 긴 로그 전체 대신 판단에 필요한 결과를 남기고 필요하면 로그 위치를 적습니다. 최근 결과를 갱신하되 중요한 실패 원인과 해결 경험은 [LESSONS.md](../../LESSONS.md)에 남깁니다.

- **성공:** 실제로 실행했고 정한 기준을 만족한 항목
- **실패:** 실제로 실행했지만 오류 또는 기준 미달이 있었던 항목
- **미실행:** 실행하지 않은 항목. 환경 부재, 권한, 범위 밖 등 이유를 함께 기록

## 새 검사 기록 양식

- 날짜 / 작업:
- 확인 대상과 완료 기준:
- 대상 커밋·변경 범위:
- 명령 또는 수동 확인 방법:
- 실행 위치 / 환경:
- 결과: 성공 · 실패 · 미실행 중 하나
- 실제 관찰 내용 또는 미실행 사유:
- 남은 확인 / 다음 조치:

프로젝트에서 실제 검사 명령을 찾으면 명령을 확인한 설정 파일이나 스크립트 경로도 함께 기록합니다. 문서만 바꾼 작업에는 코드 테스트를 새로 만들지 않습니다.
