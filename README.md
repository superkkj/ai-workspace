# ai-workspace

AI와 함께 개발하면서 코드, 진행 상황, 확인된 해결 경험을 쌓는 개인 작업 공간입니다. 이전 대화에서 정리한 개발 방식을 문서로 남기고, 다음 작업 때 필요한 내용을 다시 읽어 이어 갑니다.

- GitHub 계정: `superkkj`
- 저장소: [superkkj/ai-workspace](https://github.com/superkkj/ai-workspace)
- 공개 범위: **공개(Public)** — 2026-11-18 사용자 요청으로 전환
- 실제 연결·업로드 상태: [STATUS.md](STATUS.md)에서 확인합니다.

## 매번 이렇게 사용합니다

**계획 → 필요한 검토 → 구현 → 필요한 검사·실사용 확인 → 기록**을 기본 흐름으로 사용합니다.

1. `AGENTS.md`와 `STATUS.md`를 읽고, 관련된 `LESSONS.md`와 검사 목록을 확인합니다.
2. 만들 기능과 완료 기준을 짧게 정합니다. 영향이 큰 변경은 계획의 빠진 조건도 검토합니다.
3. 작은 단위로 구현하고, 실제 프로젝트에서 확인한 명령과 실행 방법으로 결과를 점검합니다.
4. 검사 결과는 `docs/ai/CHECKS.md`, 진행 상황과 다음 작업은 `STATUS.md`에 갱신합니다.
5. 원인과 해결법을 확인한 문제는 `LESSONS.md`에 남깁니다. 반복되는 실수라면 관련 지침이나 검사도 필요한 만큼 보완합니다.
6. 변경 내용을 확인한 뒤, 요청받은 범위에서 커밋하고 GitHub에 반영됐는지 확인합니다.

문서의 오탈자 수정처럼 영향이 작은 작업은 별도 계획서나 코드 테스트를 만들지 않습니다. 자세한 기준은 [개발 흐름](docs/ai/WORKFLOW.md)에 있습니다.

**파일 수정, 커밋, GitHub 업로드는 서로 다른 단계입니다.** 로컬에서 저장한 것만으로 GitHub에 올라가지 않습니다.

## 새 대화에서 시작할 때

> superkkj/ai-workspace의 AGENTS.md와 STATUS.md를 먼저 읽어 줘. 현재 작업에 필요한 README.md, docs/ai/WORKFLOW.md, LESSONS.md, docs/ai/CHECKS.md도 확인하고, 다음 할 일을 이어서 진행해 줘. 실제로 확인한 결과만 기록해 줘.

## 작업을 마칠 때

> 오늘 실제로 완료한 일, 남은 문제, 다음 할 일을 STATUS.md에 갱신해 줘. 실행한 검사와 결과는 docs/ai/CHECKS.md에, 원인과 해결법을 확인한 사례는 LESSONS.md에 기록해 줘. 이번 작업의 변경 내용을 확인하고 커밋해서 GitHub에 저장해 줘.

사용하는 AI 도구가 파일을 직접 읽고 수정할 수 있어야 이 흐름을 실행할 수 있습니다. 조회만 가능한 연결이라면 수정 가능한 개발 도구 또는 사용자가 변경 내용을 저장해야 합니다. 저장소에 기록한다고 모든 AI가 내용을 자동으로 영구 기억하는 것은 아닙니다.

## Codex와 Claude를 함께 쓸 때

공통 규칙은 `AGENTS.md` 한 곳에서 관리합니다. `CLAUDE.md`는 그 파일을 가져오도록 구성했습니다. 도구별 파일 읽기 방식과 확인 방법은 [개발 흐름](docs/ai/WORKFLOW.md)에 정리했습니다.

필요할 때 **Codex로 구현 → Claude로 독립 검토 → Codex로 수정·재검사**하는 방식으로 나눌 수 있습니다. 검토할 변경 범위, 완료 기준, 검사 결과를 함께 전달합니다. 두 도구를 자동 연결하는 설정은 아직 없으며, 한 도구만으로 작업을 진행해도 됩니다.

## 첫 프로젝트: 열어줘

**원하는 활동·동네·시간·예산을 올리면 사람들이 관심을 모으고, 공방·강사가 제안한 조건을 확인해 각자 참가를 확정하는 웹앱**입니다. 2026-11-18 사용자 선택에 따라 기획과 첫 구현을 진행했습니다.

핵심 흐름은 **활동 요청 → 관심 참여 → 운영자 제안 → 요청자의 제안 선택 → 참가자의 별도 확정 → 진행 완료 또는 취소**입니다. 관심 인원과 확정 인원을 구분하고, 제안 선택 뒤 조건을 바꾸거나 정원을 초과해 참가할 수 없도록 서버와 데이터베이스에서 확인합니다.

- 코드 위치: `apps/yeoreojwo/`.
- 실행 환경: Node.js 24, React·TypeScript·Vinext, Cloudflare D1. 정확한 의존성은 앱의 `package.json`과 잠금 파일을 기준으로 합니다.
- 검사 명령: 앱 폴더에서 `npm run typecheck`, `npm test`, `npm run build`.
- 로컬 실행과 DB 초기화: 앱의 `README.md`에 있는 설치·마이그레이션 순서를 따릅니다. 사용자 PC 실행은 아직 확인하지 않았습니다.
- 제외 범위: 결제·정산·환불·외부 예약 대행·문자 발송. 화면의 참가 확정은 이 서비스 안에서 의사를 기록하는 기능입니다.

타입 검사, Node·SQLite/D1 어댑터 자동 테스트 **24개**, 로컬 D1 마이그레이션과 최종 앱 소스의 production 빌드를 확인했습니다. 브라우저에서는 검색·필터·빈 결과·예시 상세·로그인 요구·모바일 메뉴와 좁은 화면 배치를 확인했습니다. 브라우저 검증 당시 실제 모집 데이터는 **0건**이었으며 화면 이해용 **예시 6건은 읽기 전용**입니다.

**실행 주소:** [열어줘 열기](https://yeoreojwo-superkkj.insightfulinlet4.chatgpt.site) — 배포 성공을 확인했으며 현재는 **소유자 전용**입니다. 공개 GitHub와 앱의 방문 가능 범위는 별개입니다. 브라우저에서는 배포 주소의 로그인 화면까지 확인했습니다.

[첫 버전의 예시 화면](docs/product/yeoreojwo-preview.jpg)은 로컬 미리보기에서 캡처했습니다.

공개 GitHub에 앱 소스와 개발 기록을 반영했고, [최종 GitHub Actions](https://github.com/superkkj/ai-workspace/actions/runs/44262860146)에서 의존성 설치·타입 검사·24개 자동 테스트·빌드·로컬 D1 준비·HTTP 통합 검사 9개가 모두 통과했습니다. 잘못된 입력 2개와, 인증·출처 거절 직후 다음 POST의 연결을 확인하는 회귀 검사 20쌍도 통과했습니다. HTTP 검사는 합성 사용자를 사용했고 자신이 만든 로컬 테스트 기록을 정리했습니다.

개발 가이드와 기획의 완료 기준을 다시 대조해, 수업 종료 직전·정확한 종료 시각과 제안 철회 후 재제안 검사를 보완했습니다. 반복된 로컬 프록시 503은 수정된 HTTP 테스트 런타임을 별도로 고정해 검증했습니다. 앱 빌드 의존성과 호스팅 인증은 유지했습니다. 실제 ChatGPT 계정 여러 개를 사용한 브라우저 전체 흐름과 사용자 PC 실행은 아직 미검증이며, 실패 이력과 최종 확인 범위는 [검사 기록](docs/ai/CHECKS.md)에 남겼습니다.

이전 [실용 앱 후보 조사](docs/research/2026-11-18-app-ideas.md)는 후보 탐색의 기록으로 보존합니다. 선택한 제품의 현재 범위는 [열어줘 기획서](docs/product/yeoreojwo-plan.md)를 기준으로 합니다.

## 기록할 때 지킬 점

- API 키, 비밀번호, 개인 인증 파일, 실제 비밀 설정값을 저장하지 않습니다.
- 공개 저장소에는 공개 가능한 개발 문서·코드·샘플만 올립니다. 앱 이용자의 실제 사진, 예약 문자, 결제·문의 자료를 커밋하지 않습니다.
- `.gitignore`는 이미 Git이 추적 중인 비밀 파일을 제거하지 않으므로 커밋할 변경 내용도 확인합니다.
- 회사 코드나 자료는 해당 자료에 적용되는 저장·접근 정책을 확인한 범위에서 다룹니다.
- 대화 원문 전체보다 결정 사항, 확인한 근거, 다음 작업을 간결하게 남깁니다.
- 커밋·푸시 완료 여부는 실제 결과를 확인해서 기록합니다.
