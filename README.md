# ai-workspace

AI와 함께 개발하면서 코드, 진행 상황, 확인된 해결 경험을 쌓는 개인 작업 공간입니다.

- GitHub 계정: `superkkj`
- 저장소: [superkkj/ai-workspace](https://github.com/superkkj/ai-workspace)
- 공개 범위: **비공개(Private)**
- 실제 연결·업로드 상태: [STATUS.md](STATUS.md)에서 확인합니다.

## 파일 역할

| 파일 | 역할 |
| --- | --- |
| [AGENTS.md](AGENTS.md) | AI가 이 저장소에서 작업할 때 따를 지침 |
| [STATUS.md](STATUS.md) | 현재 목표, 완료한 일, 막힌 점, 다음 할 일 |
| [LESSONS.md](LESSONS.md) | 원인과 해결 방법을 확인한 사례 |
| `.gitignore` | 로컬 설정과 불필요한 산출물이 Git에 추가되는 것을 줄이는 설정 |

## 매번 이렇게 사용합니다

1. 작업 시작 전에 `AGENTS.md`와 `STATUS.md`를 읽습니다.
2. 지금 할 작업과 관련된 `LESSONS.md` 내용만 확인합니다.
3. 필요한 작업을 진행하고 실제 결과를 확인합니다.
4. `STATUS.md`에 완료 내용, 남은 문제, 다음 작업을 갱신합니다.
5. 반복해서 쓸 수 있는 검증된 해결법이 있다면 `LESSONS.md`에 기록합니다.
6. 변경 내용을 확인한 뒤, 요청받은 범위에서 커밋하고 GitHub에 푸시합니다.

**파일 수정, 커밋, GitHub 업로드는 서로 다른 단계입니다.** 로컬에서 저장한 것만으로 GitHub에 올라가지 않습니다.

## 새 대화에서 시작할 때

> 이 저장소의 README.md, AGENTS.md, STATUS.md를 먼저 읽어 줘. 현재 작업과 관련된 LESSONS.md도 확인한 뒤, 다음 할 일을 이어서 진행해 줘. 실제로 확인한 결과만 기록해 줘.

## 작업을 마칠 때

> 오늘 실제로 완료한 일, 확인한 결과, 남은 문제, 다음 할 일을 STATUS.md에 갱신해 줘. 원인과 해결법을 확인한 사례가 있으면 LESSONS.md에 적용 조건과 함께 기록해 줘.

사용하는 AI 도구가 파일을 직접 읽고 수정할 수 있어야 이 흐름을 실행할 수 있습니다. 조회만 가능한 연결이라면 수정 가능한 개발 도구 또는 사용자가 변경 내용을 저장해야 합니다. 저장소에 기록한다고 모든 AI가 내용을 자동으로 영구 기억하는 것은 아닙니다.

## 첫 프로젝트

아직 선택하지 않았습니다. 만들 프로그램을 정하면 기획서와 소스 코드를 추가하고, `STATUS.md`의 목표와 다음 작업을 갱신합니다. 작업 방법이 실제로 반복될 때 필요한 지침을 보완합니다.

자동 빌드·테스트와 러너는 반복해서 검사할 작업이 생겼을 때 추가합니다. 이 초기 구성에는 자동 실행이나 배포 설정이 없습니다.

## 기록할 때 지킬 점

- API 키, 비밀번호, 개인 인증 파일, 실제 비밀 설정값을 저장하지 않습니다.
- `.gitignore`는 이미 Git이 추적 중인 비밀 파일을 제거하지 않으므로 커밋할 변경 내용도 확인합니다.
- 회사 코드나 자료는 해당 자료에 적용되는 저장·접근 정책을 확인한 범위에서 다룹니다.
- 대화 원문 전체보다 결정 사항, 확인한 근거, 다음 작업을 간결하게 남깁니다.
- 커밋·푸시 완료 여부는 실제 결과를 확인해서 기록합니다.
